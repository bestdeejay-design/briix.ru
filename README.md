# BRIIX — демо пространства помощников

> Интерактивное пространство помощников: локальные сценарии и моки, а также опциональный live через ваш media-bff. Ключ хранится только в браузере пользователя и не входит в репозиторий.

## Что сейчас в корне

Корень репозитория — статическое демо, опубликованное на GitHub Pages как `briix.ru`.

```
index.html      — оболочка приложения
demo.css        — дизайн-система, светлая/тёмная тема, адаптивность
demo.js         — состояние, маршруты, диалоги, поиск, избранное, настройки
demo-data.js    — помощники, промпты и сценарные ответы
media.js        — Медиа-студия: локальный фото/видео-мок, очередь и медиатека
media-live.js   — опциональный режим «Приватный live» (свой media-bff, см. audits/task-23-media-live-wave1.md)
media.css       — стили Медиа-студии
assets/media/   — локальные JPEG/MP4/WebM и manifest
tools/          — сборка ассетов и browser-проверки (только для разработки)
site/           — прежний сайт BRIIX (лендинг, презентация, инвесторы, финмодель)
docs/           — историческая документация продукта BRIIX (канон, только чтение)
ai-platform*/   — документы отдельного этапа API-платформы
audits/         — отчёты о проверках и задачах
```

## Возможности демо

- 6 помощников: Универсальный, Редактор, Аналитик, Разработчик, Маркетолог, Наставник.
- Главная с примерами запросов и быстрым выбором помощника.
- Диалоги со сценарными ответами, имитацией потока, остановкой, повтором и альтернативным вариантом.
- История, поиск (`Ctrl/⌘ K`), избранное для диалогов, ответов и промптов.
- Вложения-заглушки: сохраняются только имя, тип и размер; содержимое не читается.
- Настройки: тема, размер текста, плотность, имя, помощник по умолчанию, отправка по Enter, история, демонстрационная ошибка.
- Экспорт диалога в Markdown, экспорт/импорт всего состояния в JSON.
- Мобильная версия, клавиатурная навигация, пустые состояния и состояния ошибок.
- Интерфейсные приёмы из прежнего сайта в `site/`: тень шапки при прокрутке, плавное появление карточек, FAQ в справке, подсветка активного раздела настроек и явное состояние кнопки темы.
- Медиа-студия (`#/media`): бриф, локальная очередь, медиатека, избранное, скачивание кропов и экспорт. Фото и видео — локальные исходники; видео собрано ffmpeg из неподвижного кадра, это не результат нейросети.

## Запуск

Сборка и зависимости не нужны:

```bash
python3 -m http.server 3000 --bind 0.0.0.0
```

Открыть `http://localhost:3000`, Медиа-студия — `http://localhost:3000/#/media`.

Проверки и пересборка ассетов требуют отдельных dev-инструментов, но не нужны для работы сайта:

```bash
node tools/check-demo.cjs
node tools/check-media.cjs
node tools/check-media-live.cjs   # режим «Приватный live»: миграция v2, восстановление, blob, баннер
node tools/check-media-visual.cjs
python3 tools/build-media-assets.py --check --ffmpeg /path/to/ffmpeg
```

Переменные `BRIIX_URL`, `BRIIX_TEST_OUT`, `BRIIX_CHROMIUM` и `NODE_PATH` описаны в `audits/2026-11-06-demo-code-css-audit.md`.

## CI/CD демо (стенд A fonotext)

GitHub Actions (`.github/workflows/demo-ci.yml`, self-hosted runner `briix-ci` на стенде A):

- **push в `main`** = тесты + автодеплой демо в `/home/badai/briix-demo/` (атомарно: staging `briix-demo.new` + mv) — раздаёт `briix-demo.service`, `127.0.0.1:8440`.
- **PR** = только тесты (headless playwright, деплоя нет). Один job за раз (concurrency group).
- Доступ к стенду A для работы с демо **не нужен**: владелец открывает `http://127.0.0.1:8388` через `tools/briix-media-live-up.sh` (туннели `:8388→8440` демо, `:8300→8390` media-bff).

## Границы

По умолчанию включён локальный мок без inference. Опциональный live использует существующий media-bff: Qwen для текста, FLUX для изображений, MusicGen и ACE-Step для аудио; фактическая готовность проверяется по `/health` и `/v1/models`. Видео-бэкенда нет, поэтому видео остаётся локальным моком. Аккаунтов и синхронизации между устройствами нет; bearer-ключ не сохраняется в репозитории и не попадает в экспорт.
