# Как сделать бесплатный медиа-мок для BRIIX

**Дата:** 06.11.2026; сверка ссылок — 07.11.2026.  
**Статус:** практическое руководство к реализованной «Медиа-студии».  
**Важно:** мок не запускает нейросеть. Он проверяет пользовательский сценарий и интерфейс, а не качество модели.

## 1. Какой путь выбрать

| Цель | Подход | Стоимость и риск |
|---|---|---|
| Показать UX без бюджета и без регистрации | Локальные исходники + ffmpeg + очередь в браузере | Нулевой inference; нужен только CPU для сборки |
| Попробовать разные модели вручную | Hugging Face ZeroGPU / веб-песочницы | Квоты, публичность, возможный водяной знак; не SLA |
| Получить несколько коммерческих картинок бесплатно | Разовые кредиты провайдера или собственные/стоковые исходники | Проверять лицензию, водяной знак, срок хранения |
| Регулярно генерировать локально | Открытые веса + ComfyUI/ffmpeg | GPU, память, электричество и лицензии не бесплатны |
| Production для клиентов | Серверный API-адаптер + бюджет + хранение | Не начинать с ключа в браузере |

## 2. Что уже сделано в репозитории

- `index.html` подключает `media.css` и `media.js`; раздел доступен по `#/media`.
- `media.js` хранит задания в `localStorage` под ключом `briix-media-v1`.
- `assets/media/` содержит 3 JPEG, 6 MP4 и 6 WebM; общий размер около 1.94 MiB.
- `tools/build-media-assets.py` пересобирает и проверяет исходники и manifest.
- `tools/check-media.cjs` проверяет функциональные сценарии; `tools/check-media-visual.cjs` — воспроизведение, геометрию и axe.

Три визуальных направления: керамика, кофе, skincare. Для каждого видео есть landscape 1280×720 и portrait 720×1280, длительность 5 секунд, 24 fps, без звука. MP4 H.264 — основной источник, WebM VP9 — fallback.

**Происхождение:** JPEG созданы генератором изображений в рамках этой работы. Видео собраны ffmpeg из неподвижного кадра движением камеры. Это не результаты видео-модели. При замене исходников нужно сохранить источник и право использования в `manifest.json`.

## 3. Пересборка ассетов

Сам сайт остаётся статическим: runtime-зависимостей нет. Pillow и FFmpeg нужны только разработчику для пересборки.

```bash
# Из корня репозитория. Pillow можно поставить изолированно:
python3 -m pip install --target /tmp/briix-build Pillow

# Если ffmpeg уже в PATH:
PYTHONPATH=/tmp/briix-build python3 tools/build-media-assets.py

# Либо указать бинарник явно:
PYTHONPATH=/tmp/briix-build python3 tools/build-media-assets.py --ffmpeg /path/to/ffmpeg

# Проверить имена, размеры, SHA-256, схему manifest и декодирование видео:
PYTHONPATH=/tmp/briix-build python3 tools/build-media-assets.py --check --ffmpeg /path/to/ffmpeg
```

Сборка намеренно детерминирована:

- исходный JPEG уменьшается до длинной стороны ≤1400 px и сохраняется с quality 88; маленький upright RGB JPEG копируется байт-в-байт;
- применяется EXIF orientation, метаданные не переносятся в новый файл;
- 5 секунд × 24 fps = 120 кадров;
- MP4: H.264, `yuv420p`, CRF 25, `faststart`, без звука;
- WebM: VP9, CRF 36, `row-mt=1`, без звука;
- manifest хранит schema version, размеры, duration, codec, fps, frames, audio flag, SHA-256 и версии инструментов.

Повторная сборка в проверенном окружении не изменила ни один из 15 SHA-256. Это свойство recipe и зафиксированных tool versions, а не обещание для любой версии FFmpeg/Pillow.

### Как заменить исходник

1. Положить лицензированный JPEG в `assets/media/` с тем же именем или обновить `SOURCES` в скрипте.
2. Записать происхождение и лицензию в manifest через сборочный скрипт.
3. Запустить сборку и `--check`.
4. Запустить browser-проверки скачивания: фото скачивается как центральный кроп выбранного формата, видео — как готовый MP4/WebM.

Не выдавайте стоковую фотографию или pan/zoom за результат указанной модели. В интерфейсе уже есть пометка «Локальный мок» и объяснение происхождения.

## 4. Как работает браузерный мок

Состояние задания: `queued → running → ready`, плюс `error` и `cancelled`. После перезагрузки незавершённое `running` возвращается в `queued`; готовый результат не генерируется заново.

Ограничения:

- промпт 12–1500 символов;
- до 6 активных заданий и до 40 записей истории;
- favorites и активные задания защищены от вытеснения;
- пользовательские референсы: до 3 файлов PNG/JPEG/WebP по 10 MB, хранится только метаданные;
- скачивание фото: canvas center-crop под 1:1, 4:5, 16:9 или 9:16, длинная сторона ≤1600 px;
- скачивание видео: готовый локальный файл нужной ориентации;
- экспорт JSON содержит только durable-состояние;
- повреждённый storage не удаляется молча: показывается баннер и явное действие очистки.

Это локальная демонстрация, не облачная очередь и не гарантия сохранности данных.

## 6. Минимальный бесплатный пайплайн без облака

1. Взять собственный кадр продукта или лицензированный stock.
2. Сформулировать бриф: продукт, свет, композиция, движение, формат, ограничения.
3. Собрать 5-секундный pan/zoom через `tools/build-media-assets.py`.
4. Показать результат в `#/media` с пометкой «не нейросеть».
5. Скачать варианты кропа и экспортировать brief JSON.
6. Если нужен реальный inference — отправить тот же бриф в выбранную модель вручную и сравнить, не подменяя мок результатом модели без явной маркировки.

Пример логики движения из сборщика: медленный zoom с плавным easing, без резких скачков экспозиции и без появления новых объектов. Для portrait используется отдельный центральный кроп, а не растянутый landscape.

## 7. Чек-лист перед production

- [ ] Ключи только на сервере; в браузере нет секретов.
- [ ] Есть оценка цены, лимит бюджета и защита от повторного списания.
- [ ] Очередь, статусы, отмена и retry соответствуют контракту провайдера.
- [ ] Результат скачан в собственное хранилище до истечения signed URL/retention.
- [ ] Проверены лицензия модели, коммерческие права, водяные знаки и публичность.
- [ ] Есть модерация и политика чувствительных референсов.
- [ ] Проверены оплата и доступность из региона проекта.
- [ ] Ошибки понятны пользователю и не обещают генерацию там, где её нет.

## 8. Проверки репозитория

```bash
# Статический сайт, из корня:
python3 -m http.server 3000 --bind 0.0.0.0

# Browser-зависимости устанавливаются отдельно от сайта.
# Пример переменных для подготовленного окружения:
export BRIIX_URL=http://127.0.0.1:3000
export NODE_PATH=/tmp/briix-tools/node_modules
export BRIIX_CHROMIUM=/tmp/chromium

node tools/check-demo.cjs
node tools/check-media.cjs
node tools/check-media-visual.cjs
```

Скрипты пишут JSON/скриншоты в `BRIIX_TEST_OUT` или системный temp, не в рабочую страницу. Результаты текущего прогона сведены в `2026-11-06-demo-code-css-audit.md` и `task-media-local-mock.md`.
