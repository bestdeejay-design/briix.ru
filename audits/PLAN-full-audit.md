## 0.1 Курс на простоту (просьба владельца, 8 ноября)

> «мобильный интерфейс с нейронкой максимально простой: пишешь в чат, под чатом
> выбран помощник и что генерируем, результат в ленте. Все настройки — отдельно!»

Принято как продуктовое правило для телефона:

| Правило | Как соблюдено |
|---|---|
| Одно поле ввода | чат остаётся единственным местом, где человек пишет |
| Под полем ровно два выбора | помощник и «что делаем»: Ответ · Картинка · Музыка · Песня |
| Результат в ленте | карточка результата появляется прямо в диалоге и сразу попадает в кадр |
| Ничего не заполнять обязательно | жанр, темп, длительность, формат и лирика подбираются сами |
| Хочешь настроить — отдельный интерфейс | «Все настройки подробно» ведёт в прежний раздел, он не удалён |
| Веб не тронут | новый чип скрыт вне `@media (max-width:650px)` |
| Честность сохранена | у каждой карточки видна маркировка «Локальный мок, не нейросеть» / «Ваш сервер» |

Помощник **«Музыкальный продюсер»** в демо уже есть (`assistants[6]`, id `producer`):
он собирает бриф на трек. Раньше он отправлял человека заполнять форму в «Музыке» —
теперь достаточно выбрать под полем «Музыка» или «Песня» и написать одну фразу.

**Подтверждение, что лирика именно там:** `tools/media-bff-config/README.md` дважды ссылается на этот
источник — «полная композиция 150 с (**Room 7, No Knock**, лирика из `chats-audit` владельца, автор

### 1.3 Что нужно от владельца (одно действие)

GitHub → **Settings → Applications → Configure** у приложения, через которое подключена Arena →
**Repository access** → добавить `chats` (и, если нужно, `chats-audit`).
Токены в чат присылать не нужно и небезопасно — достаточно открыть доступ приложению.

После этого план такой: дерево `chats/music/` → тот же сборщик `tools/build-creative-base.cjs`
(он уже умеет дедуплицировать и шардить) → база растёт с 8202 до полного объёма, ничего в UI менять
не придётся: подписи и счётчики берутся из индекса.

### 1.4 Что работает уже сейчас

База `dj1` — не заглушка и не выдумка: 8202 трека владельца, 6499 уникальных промптов,
6133 уникальных текста, 1487 на русском. Промпты и лирика не изменены, изменена только упаковка.

## 3. Сквозной путь пользователя — что проверяем

Инструмент: `tools/check-live-stand.cjs`. Запуск: workflow `live-audit.yml` (вручную или по расписанию).
Токен берётся из окружения раннера / systemd-юнита и **никогда не печатается**.

| # | Путь пользователя | Что считается успехом |
|---|---|---|
| J1 | Открыть «Изображения», написать задумку, получить картинку | 202 → стадии → `ready`, файл отдан, PNG/JPEG по magic-байтам, размеры > 0 |
| J2 | Скачать картинку | `GET /files/{id}` отдаёт тот же байт-поток, `Content-Type` совпадает |
| J3 | «Музыка» → инструментал (MusicGen) | `ready`, m4a/mp3, `ffprobe`: кодек, длительность, обложка `attached_pic` |
| J4 | «Музыка» → песня **Flash**, лирика из базы | `ready`, вокальный джоб подписан `song.vocal`, тег `lyrics` в m4a, звук не тишина |
| J5 | «Музыка» → песня **Pro** 60–150 с | то же + структура держится, тайминг в пределах таймаута 900 с |
| J6 | Отменить задачу на середине | `cancelled`, процесс-группа убита, счётчики не текут |
| J7 | Moderation: явный запрос | `422 content_blocked` **до** очереди, текст сервера дословно |
| J8 | Moderation: художественная нагота | `202` — политика не режет разрешённое |
| J9 | Чат: обычный ответ и стрим | JSON и SSE, `max_tokens`/`temperature` уважаются (проверка пункта 4 из #28) |
| J10 | Каталог моделей | все заявленные модели присутствуют, `status` и лимиты совпадают с UI |
| J11 | Оффлайн/потеря связи в браузере | честный мок-баннер, данные не теряются |
| J12 | Мобильный контракт всех разделов | 16 экранов, `FINDINGS {}` |

J1–J10 — на раннере. J11–J12 — в песочнице и PR-гейте, уже зелёные.

## 7. Как пополнять этот план

1. Новая находка → строка в §5 со следующим `F-xx`, важность и статус «открыто».
2. Правка → коммит с номером находки в сообщении, статус в §5 меняется на ✅ с хешем.
3. Новый маршрут пользователя → строка в §3 и проверка в `tools/check-live-stand.cjs`.
4. Прогон живого аудита → результаты в `audits/evidence/live-audit-<дата>.json`, ссылка из §4.
5. Ничего не удалять: закрытые находки остаются как история и как защита от возврата бага.
