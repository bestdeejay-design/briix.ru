# Issue #97 — этап 1, промежуточный отчёт

**Статус: работа не завершена, не для приёмки и не для деплоя.** Координатор выдал GO с изменениями в комментарии #97: IndexedDB per-ник + безопасная миграция и fallback, затем 1b (осциллограмма и повтор), сервер не трогать. Исследование: `audits/task-97-sessions-research.md`.

## Что сделано

- `studio/session-store.js` — изолированная заготовка IndexedDB-хранилища: версия схемы, атомарная первичная миграция существующих `briix-studio-feed-<nick>` / `briix-studio-history-<nick>`, точная резервная копия исходных строк в той же транзакции, сохранение исходных localStorage-ключей, отказ при повреждённом JSON, независимые профили, ревизия и отклонение конкурентной записи вместо перезаписи новых данных. Сохранение не может уничтожить резервную копию. Файл **не подключён к студии**.
- `tools/check-session-store.cjs` — проверки этой заготовки в реальном Chromium IndexedDB: параллельная миграция из двух вкладок, 106 записей без обрезания, сохранность legacy/backup, конфликт конкурентных записей, разные ники, повреждённый JSON с повторной попыткой, недоступность IDB/storage и симуляция ошибки квоты при записи. Это не сквозной тест миграции приложения.
- `studio/studio.js` — загрузка файлов не отправляет bearer на чужой origin и не следует за redirects; ошибку недоверенного адреса возвращает как ошибку, а не отправляет запрос. Это намеренно запрещает даже доверенный redirect, пока серверный контракт redirect не подтверждён. `tools/check-studio.cjs` проверяет оба сценария; `studio/index.html` обновляет cache key изменённого скрипта.

## Проверки

- `check-session-store.cjs`: PASS, Chromium + реальный IndexedDB (синтетические тестовые данные, не данные владельца). Ошибка квоты симулирована при `IDBObjectStore.add`, реальный лимит устройства не измерен.
- `check-studio.cjs`: 29/29, локальный mock BFF; `check-wait-phrases.cjs`: 10/10. Эти сюиты проверяют старое поведение студии; в частности, старый тест всё ещё подтверждает, что «Новый чат» стирает ленту, а не новую функциональность.
- `node --check` для двух скриптов и `git diff --check` — успешно. Локально использовались временные Playwright и Chromium, они не включены в репозиторий.

## Обязательно осталось сделать до приёмки

1. Реализовать утверждённый fallback на localStorage при недоступности IndexedDB с честным сообщением пользователю, отказом от потери данных и безопасной политикой конфликтов/переключения между хранилищами. Заготовка пока возвращает `idb_unavailable` и **не является fallback**. Проверить недоступность/квоту обоих хранилищ и приватный режим.
2. Подключить хранилище к UI и ввести drawer сессий, безопасный новый чат, возврат в сессию, контекст, сохранение снимка полных входных данных и ссылку трек↔сессия. До выполнения **«Новый чат» всё ещё удаляет текущую историю**. Не заменять существующие legacy-ключи пустыми данными. Проверить на реальных данных владельца, не только синтетике.
3. Перепроектировать операции с захваченным `nick/sessionId` до await, чтобы результат попадал в исходную сессию при переключении; проверить конкурентные операции, logout, reload и остановку. Проверить сквозной пользовательский сценарий и только после зелёной интегрированной миграции переходить к этапу 1b.
4. Выполнить честные ошибки/повтор библиотеки при 429/401/404, измерения шторма на mock и живом стенде, отдельную генерацию картинки обложки с превью, этап 1b waveform с бюджетом памяти и native fallback и «Повторить с правками». Настоящий audio-to-audio и привязка обложки к файлу ждут INFRA #95; живой retention — INFRA #94. Не выдавать временное доступное изображение за замену обложки трека.
5. Обновить сквозные сюиты, провести ревью, CI, живой аудит и iPhone Safari/VoiceOver по issue. Никакие из этих этапов ещё не выполнены; живой backend и реальное устройство в этой среде недоступны. Влияние запрета redirect на живой backend также не проверено.

Сервер и длительность генерации не менялись. Текущая работа — промежуточная; **вердикт GO на дизайн не равен приёмке реализации**.
