# Отчёт: infra#93 — полный трек (duration без дефолта 30) + трим хвоста тишины

Дата: 14.11.2026. Стенд: fonotext-stand A (badai, без root). Ветка: `fix/infra93-full-track`.

## Корень (подтверждён аудитом цепочки job-f78bfd062f04082b)

- В `bff.py` было `vdur = params.get("duration", 30)` (валидация) и
  `"duration": j["params"].get("duration", 30)` (сборка request-JSON для ace-lm).
- Джоба владельца: 663 символа лирики в params, **duration клиентом не прислан** →
  bff подставил 30 → в request-JSON ушло `duration: 30`.
- В acestep.cpp (`src/metadata-fsm.h:647`) request-duration > 0 форсируется в YAML
  метадаты (`prompt.h:252`) и LM constrained им → модель не может удлинить трек.
  Факт: результат job-f78bfd062f04082b — **29.6 c** при 663-символьной лирике
  (файл `results/job-f78bfd062f04082b.wav` на стенде).
- Лирика не «обрезалась» — она физически не помещается в 30 с: синтез останавливается
  по лимиту кодов, рассчитанному из duration (границы синтеза, не гонка, не обрезка текста).
- Границы acestep.cpp проверены: без ключа `duration` в request-JSON
  `request.cpp:157` ставит 0.0 → YAML-строка `duration:` не пишется → LM сам выбирает
  длину по лирике; fallback 120 с (`metadata-fsm.h:666`), жёсткий физический потолок
  **600 с** (`metadata-fsm.h:669`) — оставлен как потолок безопасности, совпадает с
  `max_duration: 600` в каталоге VOCAL_MODELS.

## Что сделано (bff.py, /home/badai/briix-media/media-bff/)

1. **duration без дефолта** (решение владельца из комментария в #93 от 14.11):
   - валидация: `vdur = params.get("duration")`; проверка 5..max_duration только если
     прислан явно; иначе 400 — как раньше;
   - request-JSON для ace-lm: ключ `duration` добавляется только если клиент прислал
     его явно (строка 561 — метадата `_job_public` — уже была условной, не тронута).
2. **Трим хвостовой тишины** — новая функция `trim_tail_silence(jid)`, вызывается в
   `vocal_worker` после синтеза, до `music_package` (mux в m4a):
   - `ffmpeg silencedetect noise=-40dB:d=1.5`; трим только если последний блок тишины
     продолжается до EOF (учтено, что ffmpeg печатает `silence_end` ровно в dur) и его
     длина ≥ 2 с и начало ≥ 5 с (середину трека не трогаем);
   - обрезка `cut = tail_start + 1.0` с `afade out` ~1.5 с; до 3 проходов — после
     первого fade смежный участок уходит ниже порога -40 dB и склеивается с тишиной;
   - деградация мягкая: нет тишины — файл не изменяется; сбой трима не роняет джобу.
3. **Бэкап/рестарт**: `bff.py.bak-20261115-duration` на стенде;
   `systemctl --user restart media-bff` — активен. MUSIC_BACKEND (cpu-a) и юнит-конфиги
   не тронуты. Клиентский контракт не менялся (duration в ответе не появился).
