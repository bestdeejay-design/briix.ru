# Справка: fonotext-стенды — что есть для арены (07.11.2026)

Поставил: координатор инфраструктуры — поручение владельца. Назначение файла: дать
агенту-арене **факты о ресурсах**, чтобы она могла предложить, что из этого можно
использовать под сервис BRIIX. Это справка-снимок, не мануал: адреса, порты, доступы
и юниты намеренно **не приводятся** (публичный репо) — всё это у координатора инфры.

## 1. Что за стенды

Два Linux-сервера в закрытой сети заказчика (вне общего облака) + локальный стенд на
макбуке владельца. Один сервер смотрит наружу (edge: TLS-терминация, деплой-раннер),
второй — только внутренний (GPU-обработчик, наружу не доступен вовсе). Между собой
соединены в приватную LAN.

## 2. Ресурсы и что на них живёт

### Стенд A (edge) — 20 ядер / 94 ГБ RAM / ~240 ГБ свободного диска

| Ресурс | Состояние |
|---|---|
| LLM-инференс Ollama (`qwen3:4b-instruct`, 2 параллельных слота) | ✅ работает |
| CI/CD self-hosted раннер (единственный CI одной из организаций GitHub) | ✅ работает, трогать нельзя |
| Веб-панель приложения (API + дашборд за TLS через Caddy) | ✅ работает (прод fonotext) |
| Резервный CPU-инстанс Ollama (второй на edge-стенде) | ⚠️ выключен (допустимо) |

### Стенд B (GPU-обработчик, изолирован) — GPU RTX 3050 8 ГБ · 12 ядер / 31 ГиБ RAM / диск 1.7 ТБ свободно (замер live 07.11)

| Ресурс | Состояние |
|---|---|
| **Silero TTS** (RU-голоса, HTTP API, WAV 48k) | ✅ работает, проверен 05.11 |
| Ollama-инференс ×3 инстанса: pipeline / asr / bulk (по 2 слота, `qwen3:4b-instruct`) | ✅ работает |
| **faster-whisper large-v3-turbo** (веса — единственная копия) | ✅ веса на месте (ASR/транскрипция RU) |
| Внешний интернет | ❌ нет вообще (egress закрыт) — ставить можно только то, что переносится файлами |

### Локальный стенд (макбук) — механика пайплайна без GPU
Каналы → ASR → слияние → метрики; для экспериментов механики, не производительности.

## 3. Что арена может предполагать доступным «как ресурс»

- **LLM**: qwen3:4b (RU-адекватный, быстрый на 8 ГБ VRAM), 4 инстанса суммарно.
- **Голос**: синтез речи RU (Silero: несколько женских голосов) + распознавание RU
  (faster-whisper large-v3-turbo). Готовый TTS-сервис уже отдаёт audio/wav по HTTP.
- **CI/CD**: в инфре есть GH-раннеры под деплой (но раннер A — прод fonotext, под новые
  задачи инфра выделит отдельный контур по запросу).
- **Веб/TLS**: Caddy с автосертификатами как паттерн публикации HTTP-сервисов.
- **Postgres/MariaDB**: в инфре есть (прод-стек отдельного проекта), новые БД — по
  запросу, не на прод-данных.

## 4. Жёсткие ограничения (не предлагать в нарушение)

1. **Fonotext-прод приоритетен.** Пайплайн обработки звонков заказчика — главная
   нагрузка; любое предложение арены, которое заметно ест GPU/CPU/диск стендов,
   согласуется с координатором инфры до реализации.
2. **NFS-хранилище источников звонков заполнено на 99%** — туда ничего не писать.
3. **Стенд B без интернета** — модели/зависимости доставляются файлами через A;
   сервисы, которым нужен исходящий интернет, на B не живут.
4. **Секреты/адреса не публикуются** — даже для внутренних задач: только
   через координатора инфры.
5. **Агенты BRIIX не ходят на серверы напрямую** — доступ выдаётся координатором под
   задачу, минимум прав, отзыв после.

## 5. Как запрашивать ресурс

Issue в приватный репо `bestdeejay-design/infra`, label **`to:infra`** (шаблон:
«Поставил: <кто> · проект BRIIX · что нужно · зачем»). Координатор отвечает планом
и оценкой размера. Канон: [SERVICE-CATALOG.md в infra] — 10 услуг (хостинг, БД,
CI/CD, домены, бэкапы, мониторинг, доступы).
